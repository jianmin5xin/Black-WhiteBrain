# 灰质-白质自举智能体白皮书 v1.0

## 一种面向通用环境的自适应执行智能体架构

---

## 版本信息

**版本**：v1.0  
**定位**：技术架构白皮书  
**主题**：新一代自适应执行智能体模型

## 执行摘要

当前 AI Agent 正在从“对话式模型”走向“行动型系统”。大语言模型已经能够理解复杂任务、生成代码、调用工具、分析环境，并在一定程度上完成软件工程、网页操作、游戏控制、机器人规划等任务。然而，现有智能体系统仍然面临一个根本性瓶颈：

> 它们可以临时完成任务，却难以把成功经验稳定沉淀为低延迟、可复用、可迁移的执行能力。

当前多数 Agent 的运行方式仍然是：

```text
观察环境 → 调用大模型推理 → 调用工具 → 得到反馈 → 再调用大模型推理
```

这种模式适合慢速思考，但不适合高频、重复、低延迟、风险敏感或需要长期学习的任务。它存在响应慢、成本高、重复思考、技能不可沉淀、执行面依赖预设工具等问题。

本白皮书提出一种新的通用智能体架构：

> **灰质-白质自举智能体**

该模型的核心思想是：

> **未来智能体的竞争，不是大模型每一步都思考得多聪明，而是谁能把思考过、验证过、成功过的经验，沉淀成可复用、可调参、可低延迟执行的灰质技能。**

在该架构中：

- **白质层**负责慢速推理、环境理解、失败复盘、工具生成、策略调整与技能编译；
- **灰质层**负责低延迟执行、快速反应、动作映射、已验证技能调用；
- **自举层**负责发现环境中的感知面、执行面、反馈面，并将它们桥接为可执行组件；
- **海马层**负责记录经验、失败片段、成功轨迹、参数变化、技能版本和环境画像；
- **元目标层**负责驱动系统持续追求生存性、效率、适应性、安全性、智慧增长与技能沉淀；
- **安全层**负责权限控制、风险分级、沙盒验证、回滚机制、限速机制和禁止动作拦截；
- **灰质编译层**负责把白质层的慢速推理成果，转化为灰质层可快速调用的技能卡。

该架构不局限于具身智能。智能体的“身体”不必是机械臂、电机或传感器，也可以是 Shell、浏览器、文件系统、HTTP API、屏幕截图、虚拟手柄、数据库、Docker、Git、摄像头、OCR、YOLO、MCP 工具或云服务接口。

因此，本模型的核心不再是“让 AI 拥有某一种固定身体”，而是：

> **让 AI 进入任意环境后，先发现自己能够感知什么、执行什么、验证什么，再自动生成桥接组件，将成功行为沉淀为灰质技能。**

一句话总结：

> **白质层制造灰质层，灰质层释放白质层，元目标层驱动二者共同进化。**

# 第一章：背景与问题

## 1.1 从语言模型到行动智能体

过去的 AI 系统主要以语言交互为中心。用户提出问题，模型生成答案。这种系统擅长解释、写作、推理和总结，但它本质上仍然停留在“信息处理层”。

随着工具调用、代码执行、浏览器自动化、MCP、机器人控制、多模态模型和软件工程 Agent 的发展，AI 正在进入新的阶段：

```text
回答问题的模型 → 调用工具的 Agent → 能够自我扩展执行能力的智能体
```

第一阶段的模型会“说”。

第二阶段的 Agent 会“用工具”。

第三阶段的智能体必须会“造工具、训练技能、沉淀经验、迁移能力”。

灰质-白质自举智能体正是面向第三阶段提出的系统架构。

---

## 1.2 当前 Agent 的核心瓶颈

### 1.2.1 高层推理强，低层执行弱

大语言模型擅长理解复杂目标，但不适合直接控制高频动作。

例如：

```text
游戏中对手跳入攻击，不能等待大模型慢慢分析后再对空；
机器人脚底打滑，不能等待大模型分析完原因后再伸手撑地；
网页弹窗出现，关闭弹窗不需要每次重新推理；
软件服务端口冲突，常见诊断流程不应该每次重新写一遍。
```

这些任务需要低延迟、稳定、可复用的执行层。

也就是说，智能体不能只有“理性思考”，还必须有“行动本能”。

---

### 1.2.2 每次重新思考，缺少经验沉淀

许多 Agent 即使完成了一次任务，也不会形成真正可复用的能力。

它们往往是：

```text
第一次遇到问题 → 调用大模型分析
第二次遇到类似问题 → 再次调用大模型分析
第三次遇到类似问题 → 继续重新分析
```

这造成两个后果：

1. **成本高**：大量重复推理消耗模型调用成本和时间；
2. **成长慢**：系统没有把成功经验变成未来的自动化能力。

真正的智能学习应该是：

```text
第一次靠推理
第二次靠规则
第三次靠技能
第四次变成本能
```

灰质-白质模型的核心，就是建立这种“从推理到本能”的沉淀机制。

---

### 1.2.3 执行能力依赖预设工具

很多 Agent 只有在开发者预先给它工具时，才能执行任务。

给它浏览器，它会打开网页。

给它 Shell，它会执行命令。

给它 API，它会调用接口。

但真正的自适应智能体进入新环境后，首先应该主动判断：

```text
我现在能看到什么？
我现在能控制什么？
我现在能验证什么？
我现在缺什么工具？
我能不能自己写一个桥接组件？
```

例如：

```text
发现摄像头 → 建立视觉输入；
发现截图能力 → 建立屏幕感知；
发现本地端口 → 建立服务诊断；
发现电机接口 → 建立运动控制；
发现游戏窗口 → 建立虚拟手柄映射；
发现 API 文档 → 自动生成 API client。
```

这就是“自举能力”。

---

### 1.2.4 缺少长期元目标

许多 Agent 只追求完成当前任务，而不追求长期变强。

但真正的智能体不应只问：

```text
这次任务怎么完成？
```

还应该问：

```text
我怎样下次更快完成？
我怎样降低失败概率？
我怎样减少大模型调用？
我怎样把这次经验变成技能？
我怎样在新环境中更快适应？
我怎样避免不可逆损失？
```

因此，系统需要一个元目标层，驱动智能体持续追求：

- 生存性；
- 安全性；
- 效率；
- 适应性；
- 技能沉淀；
- 智慧增长；
- 跨环境迁移。

---

## 1.3 本白皮书的目标

本文提出的灰质-白质自举智能体，目标不是替代所有现有 Agent，而是提出一种更完整的系统范式：

```text
让大模型不再只是一步步思考，
而是学会制造低延迟执行能力。
```

具体目标包括：

1. 建立一种通用的智能体分层架构；
2. 定义灰质层、白质层、自举层、海马层、元目标层和安全层；
3. 提出“灰质编译”和“技能卡”机制；
4. 设计智能体在陌生环境中的自举流程；
5. 给出软件、游戏、网页、机器人等场景下的适配方式；
6. 提出 MVP 实现路线；
7. 定义评估指标与安全治理原则；
8. 描绘未来技能生态与跨环境智能体的发展愿景。

# 第二章：核心概念

## 2.1 灰质-白质隐喻

本模型借用“灰质”和“白质”作为认知系统隐喻，而不是严格的神经科学定义。

其中：

```text
灰质层 = 快速执行、反射、技能、本能、低延迟动作映射
白质层 = 慢速推理、规划、分析、工具生成、技能编译
```

灰质层负责“来不及想时怎么做”。

白质层负责“为什么失败、如何改进、如何训练下次自动完成”。

二者共同构成双速智能结构：

```text
快系统：灰质层
慢系统：白质层
成长机制：白质层将成功经验编译成灰质技能
```

---

## 2.2 灰质层

灰质层是智能体的低延迟执行系统。

它可以是规则表、行为树、小型神经网络、脚本、驱动程序、API wrapper、视觉识别管线、浏览器自动化流程、机器人运动原语或软件诊断工具。

灰质层的核心特征：

1. **低延迟**：不依赖大模型逐步推理；
2. **可执行**：直接连接环境中的执行面；
3. **可复用**：可在相似场景中重复调用；
4. **可测试**：具有明确输入、输出、指标；
5. **可调参**：白质层可以调整阈值、权重、延迟、风险偏好；
6. **可版本化**：每个技能都有版本和历史记录；
7. **可回滚**：技能升级失败后可以回到旧版本。

灰质层的定义：

> **灰质层是当前环境中已经验证过、可快速调用、低成本执行、可复用的行动能力集合。**

---

## 2.3 白质层

白质层是智能体的慢速理性系统。

它通常由大语言模型、多模态模型、规划器、代码生成器、工具调用器、失败分析器和策略优化器组成。

白质层的职责包括：

1. 理解用户目标；
2. 识别环境类型；
3. 发现感知面、执行面、反馈面；
4. 判断当前灰质层是否足够；
5. 分析失败原因；
6. 提出策略假设；
7. 设计低风险实验；
8. 生成工具、脚本或适配器；
9. 调整灰质技能参数；
10. 决定是否固化新技能；
11. 合并、废弃或升级旧技能；
12. 为长期目标服务。

白质层的本质不是“永远亲自执行”，而是：

> **发现问题、解释问题、生成能力、训练本能。**

---

## 2.4 自举层

自举层是智能体进入陌生环境后的“能力发现与桥接系统”。

它要回答三个基本问题：

```text
我能感知什么？
我能执行什么？
我能如何判断执行是否成功？
```

对应三类环境接口：

| 类型 | 定义 | 示例 |
|---|---|---|
| 感知面 | 智能体能获取的信息来源 | 摄像头、截图、日志、文件、API 返回、传感器 |
| 执行面 | 智能体能影响环境的通道 | Shell、鼠标、键盘、电机、API、文件写入、虚拟手柄 |
| 反馈面 | 智能体判断行动结果的依据 | 返回值、日志变化、测试结果、画面变化、传感器反馈 |

自举层的输出是“环境能力画像”。

例如：

```json
{
  "environment_type": "software_project",
  "perception_surfaces": ["filesystem", "logs", "config_files"],
  "execution_surfaces": ["shell", "python", "git"],
  "feedback_surfaces": ["test_result", "exit_code", "health_check"],
  "missing_capabilities": ["browser_automation"],
  "recommended_adapters": ["test_runner", "log_analyzer", "health_checker"]
}
```

---

## 2.5 海马层

海马层是经验记忆系统。

它记录智能体在环境中的运行历史，包括：

- 最近事件窗口；
- 失败片段；
- 成功轨迹；
- 环境画像；
- 参数调整记录；
- 技能卡版本；
- 训练样本；
- 假设验证结果；
- 未解决问题；
- 可迁移经验。

海马层不是简单日志，而是结构化经验库。

它的作用是：

```text
为白质层提供复盘材料；
为灰质层提供训练样本；
为未来任务提供可检索经验；
为技能升级提供证据。
```

---

## 2.6 元目标层

元目标层是整个系统的最高驱动力。

它解释了为什么智能体要不断训练技能、沉淀经验和优化自身。

元目标层的核心目标包括：

| 目标 | 含义 |
|---|---|
| 生存性 | 避免系统崩溃、损坏、不可恢复失败 |
| 安全性 | 避免越权、破坏、不可逆损失 |
| 任务成功率 | 更可靠地完成当前目标 |
| 效率 | 降低时间、算力、能耗、调用成本 |
| 适应性 | 在新环境中更快建立能力 |
| 技能沉淀 | 把重复成功经验转化为技能 |
| 泛化性 | 将技能迁移到相似环境 |
| 智慧增长 | 让未来任务更容易完成 |

简化目标函数可以表达为：

```text
总价值 =
任务成功收益
+ 生存收益
+ 安全收益
+ 效率收益
+ 适应收益
+ 新技能收益
+ 泛化收益
- 风险成本
- 失败成本
- 能耗成本
- 重复思考成本
- 不可逆损失成本
```

灰质层为什么要不断训练技能卡？

因为元目标层要求系统：

```text
不但要完成当前任务，
还要让未来的自己更强、更稳、更快、更省。
```

---

## 2.7 安全层

安全层贯穿整个系统。

它负责判断：

```text
这个动作是否授权？
是否可能造成破坏？
是否可回滚？
是否影响真实用户？
是否涉及生产环境？
是否涉及物理风险？
是否存在越权或攻击行为？
```

安全层不是外部补丁，而是元目标层中“生存性”和“长期稳定性”的具体实现。

风险等级如下：

| 风险等级 | 示例 | 处理方式 |
|---|---|---|
| 低风险 | 读文件、读日志、截图、运行本地测试 | 可自动执行 |
| 中风险 | 修改本地配置、重启本地服务、调参数 | 需要沙盒或回滚 |
| 高风险 | 删除数据、写数据库、控制真实电机 | 需要强约束和明确授权 |
| 禁止 | 未授权扫描、绕过权限、攻击第三方系统 | 不执行 |

# 第三章：核心原理

## 3.1 双速认知原理

灰质-白质自举智能体采用双速结构。

```text
灰质层：快，负责执行与反应。
白质层：慢，负责理解与改造。
```

这种分工解决了大模型 Agent 的核心问题：

```text
大模型推理能力强，但实时性不足；
低层脚本执行快，但适应性不足。
```

因此，本模型让二者结合：

```text
白质层负责生成和优化灰质层；
灰质层负责快速执行白质层沉淀下来的能力。
```

---

## 3.2 环境自举原理

智能体进入环境后，不应立即执行复杂任务，而应先建立环境能力画像。

标准流程：

```text
识别环境类型
  ↓
发现感知面
  ↓
发现执行面
  ↓
发现反馈面
  ↓
评估风险
  ↓
生成最小可执行动作
  ↓
测试动作是否有效
  ↓
注册临时技能
```

例如在软件项目中：

```text
发现 package.json → 识别 Node 项目 → 找到 npm test → 运行测试 → 生成 test_runner 技能
```

例如在游戏环境中：

```text
发现屏幕截图 → 识别游戏窗口 → 建立 HUD 检测 → 建立虚拟手柄动作 → 生成视觉反应技能
```

例如在机器人环境中：

```text
发现电机接口 → 读取控制协议 → 写 motor_driver → 写 emergency_stop → 测试低速动作 → 注册移动技能
```

---

## 3.3 灰质编译原理

灰质编译是本模型的核心机制。

它把白质层的慢速推理结果，转化为灰质层可低延迟执行的技能卡。

完整过程：

```text
白质层发现重复问题
  ↓
判断值得沉淀
  ↓
定义状态空间
  ↓
定义动作空间
  ↓
选择策略形式
  ↓
生成规则、脚本、小模型或行为树
  ↓
加入安全边界
  ↓
运行测试
  ↓
调参优化
  ↓
记录指标
  ↓
固化技能卡
```

灰质编译不是单纯“保存代码”，而是把执行能力标准化为：

```text
输入 → 状态编码 → 策略判断 → 动作输出 → 反馈记录 → 可调参数 → 安全约束
```

---

## 3.4 失败驱动学习原理

失败不是系统异常，而是技能成长入口。

当灰质层执行失败时，系统不应只重试，而应进入失败复盘闭环：

```text
执行失败
  ↓
海马层记录上下文
  ↓
白质层解释失败原因
  ↓
生成多个假设
  ↓
选择低风险实验
  ↓
调整参数或结构
  ↓
再次执行
  ↓
成功则沉淀
  ↓
失败则继续搜索
```

例如：

```text
湿滑地面摔倒
  ↓
灰质层触发保护性反射
  ↓
白质层判断可能速度太快、步幅太大、摩擦不足
  ↓
尝试小步慢走
  ↓
成功后固化 slippery_surface_gait 技能
```

软件场景中也是一样：

```text
启动服务失败
  ↓
读取日志
  ↓
判断可能端口占用
  ↓
生成端口检测工具
  ↓
确认端口冲突
  ↓
调整启动参数
  ↓
固化 local_service_startup_repair 技能
```

---

## 3.5 固定结构与可调参数分离原理

灰质技能不应频繁被白质层重写代码。

正确方式是将技能拆成：

```text
稳定结构 + 可调参数
```

稳定结构包括：

- 感知入口；
- 状态编码器；
- 动作映射逻辑；
- 执行适配器；
- 安全边界；
- 日志格式。

可调参数包括：

- 检测阈值；
- 反应延迟；
- 动作权重；
- 风险偏好；
- 重试次数；
- 最大速度；
- 置信度下限；
- fallback 策略。

原则：

```text
先调参数，再改结构，最后换模型。
```

# 第五章：技能卡标准

## 5.1 技能卡定义

技能卡是灰质层的基本资产单位。

一张技能卡代表一个已经验证过、可以被调用、可以被调参、可以被测试、可以被版本管理的执行能力。

技能卡不是单纯 prompt，也不是单纯代码，而是包含完整执行语义的能力封装。

---

## 5.2 技能卡字段

标准技能卡应包含：

| 字段 | 说明 |
|---|---|
| skill_id | 技能唯一标识 |
| name | 技能名称 |
| environment_type | 适用环境类型 |
| perception_sources | 感知输入来源 |
| execution_surfaces | 执行输出通道 |
| feedback_surfaces | 反馈判断来源 |
| state_encoder | 状态编码方式 |
| policy | 策略逻辑 |
| action_adapter | 动作执行适配器 |
| tunable_params | 可调参数 |
| safety | 安全边界 |
| metrics | 运行指标 |
| tests | 测试入口 |
| version | 版本 |
| status | 生命周期状态 |

---

## 5.3 技能卡目录结构

```text
skills/
  skill_id/
    manifest.json       技能说明
    skill.py            技能主逻辑
    config.json         可调参数
    tests.py            测试用例
    stats.json          运行指标
    history.jsonl       版本和调参记录
    samples/            训练样本或失败片段
    rollback/           可回滚版本
```

---

## 5.4 技能生命周期

```text
候选技能
  ↓
临时技能
  ↓
沙盒验证技能
  ↓
灰质技能
  ↓
成熟技能
  ↓
通用技能
  ↓
废弃 / 合并 / 重构
```

| 阶段 | 含义 |
|---|---|
| 候选技能 | 白质层认为值得生成 |
| 临时技能 | 已有最小实现，未充分测试 |
| 沙盒验证技能 | 在安全环境中通过初步测试 |
| 灰质技能 | 可在真实任务中调用 |
| 成熟技能 | 有足够成功记录，可默认调用 |
| 通用技能 | 可跨环境迁移 |
| 废弃/合并 | 被更优技能替代 |

# 第六章：运行流程

## 6.1 新环境进入流程

当智能体进入一个陌生环境时，标准流程如下：

```text
1. 接收目标
2. 识别环境类型
3. 发现感知面
4. 发现执行面
5. 发现反馈面
6. 生成环境能力画像
7. 安全层评估权限与风险
8. 白质层判断缺少哪些能力
9. 自举层生成最小适配器
10. 灰质编译层封装临时技能
11. 沙盒测试
12. 灰质层执行
13. 海马层记录反馈
14. 白质层复盘
15. 成功后注册正式技能卡
```

---

## 6.2 常规任务执行流程

当已有成熟技能时：

```text
目标输入
  ↓
白质层检索技能库
  ↓
选择合适灰质技能
  ↓
安全层检查
  ↓
灰质层执行
  ↓
海马层记录
  ↓
根据结果更新指标
```

此时，大模型不需要每一步都参与。

白质层只在以下情况介入：

1. 灰质技能失败；
2. 环境发生变化；
3. 风险升高；
4. 当前技能不适用；
5. 需要生成新工具；
6. 需要做策略级调整。

---

## 6.3 失败复盘流程

```text
灰质技能执行失败
  ↓
海马层记录完整上下文
  ↓
白质层判断失败类型
  ↓
生成原因假设
  ↓
选择低风险验证方案
  ↓
优先调参数
  ↓
若无效，则改结构
  ↓
若仍无效，则训练或替换模型
  ↓
成功后更新技能卡
```

---

## 6.4 技能更新流程

技能更新分三类。

### 参数更新

优先级最高，风险最低。

例如：

```text
降低反应延迟
提高检测阈值
增加防御权重
减少重试次数
降低移动速度
```

### 结构更新

当参数无法解决问题时使用。

例如：

```text
增加 fallback
修改行为树
增加异常分支
替换状态编码器
增加新的检测器
```

### 模型更新

当结构调整仍不足时使用。

例如：

```text
训练小型策略网络
替换 YOLO 模型
蒸馏行为树为神经网络
微调视觉分类器
```

# 第八章：与现有方向的关系

当前已有多个方向与本模型的部分思想相近，但它们通常只覆盖其中一部分能力。

## 8.1 与代码技能库型 Agent 的关系

一些智能体系统已经开始让大模型生成、保存和复用代码技能。这与本模型中的“白质层生成灰质技能”高度相关。

差异在于：

```text
代码技能库型 Agent 更关注任务代码复用；
灰质-白质自举智能体更关注通用环境中的感知面、执行面、反馈面发现，以及技能卡生命周期管理。
```

---

## 8.2 与屏幕控制型 Agent 的关系

屏幕控制型 Agent 通过截图理解环境，并用键鼠操作软件或游戏。

这对应本模型中的：

```text
感知面：截图 / OCR / 视觉模型
执行面：鼠标 / 键盘 / 虚拟控制器
灰质层：快速 UI 或游戏动作技能
白质层：策略规划与失败复盘
```

本模型进一步强调：这些操作流程不应只是临时动作，而应沉淀为可版本化技能卡。

---

## 8.3 与机器人分层控制的关系

机器人领域长期存在高层规划和低层控制的分工。

本模型与其相似之处在于：

```text
高层负责规划；
低层负责控制；
安全层负责约束。
```

不同之处在于，本模型强调：

1. 智能体身体不固定；
2. 执行面可以是软件工具、API、屏幕、浏览器或电机；
3. 白质层可以自动生成桥接组件；
4. 成功经验被标准化为技能卡；
5. 元目标层驱动长期智慧增长。

---

## 8.4 与通用工具协议的关系

MCP、插件系统、函数调用协议等，为智能体连接工具提供了基础设施。

这些协议解决的是：

```text
模型如何调用外部工具？
```

灰质-白质自举智能体进一步追问：

```text
模型如何发现自己需要什么工具？
模型如何生成新工具？
模型如何验证工具有效？
模型如何把工具沉淀成技能？
模型如何让技能随着经验升级？
```

因此，本模型可以建立在通用工具协议之上，但目标是更高层的自适应执行架构。

---

## 8.5 本模型的独特性

| 维度 | 现有普通 Agent | 灰质-白质自举智能体 |
|---|---|---|
| 执行方式 | 大模型逐步调用工具 | 灰质层低延迟执行 |
| 工具来源 | 多依赖预设工具 | 可发现、生成、验证工具 |
| 成长机制 | 记忆或上下文增强 | 技能卡沉淀与灰质编译 |
| 环境适应 | 依赖已有接口 | 感知面、执行面、反馈面自举 |
| 失败处理 | 重试或重新规划 | 复盘、假设、调参、升级技能 |
| 长期目标 | 完成当前任务 | 生存、效率、安全、智慧增长 |
| 技能管理 | 零散脚本或记忆 | 标准化技能生命周期 |

# 第九章：MVP 实现方案

## 9.1 MVP 总目标

第一版 MVP 不追求完全通用智能，而是验证一个核心闭环：

```text
发现执行面 → 生成工具 → 执行任务 → 记录失败 → 调参优化 → 固化技能卡
```

---

## 9.2 推荐 MVP 场景

建议优先选择软件环境或游戏环境，而不是直接选择物理机器人。

原因：

1. 风险低；
2. 成本低；
3. 可回放；
4. 易测试；
5. 易记录；
6. 易版本管理；
7. 容易验证技能卡机制。

---

## 9.3 MVP 场景 A：本地软件项目自举 Agent

### 目标

智能体进入一个陌生本地代码项目，自动建立基础操作能力。

### 最小能力

```text
读取目录
识别语言
读取 README
发现启动命令
发现测试命令
运行测试
读取日志
生成诊断技能卡
```

### 成功标准

1. 能自动识别项目类型；
2. 能找到测试或启动入口；
3. 能运行低风险命令；
4. 能记录失败日志；
5. 能生成至少一张技能卡；
6. 下次进入相似项目时能复用技能。

---

## 9.4 MVP 场景 B：游戏视觉反应 Agent

### 目标

智能体通过截图识别状态，并生成快速动作映射。

### 最小能力

```text
屏幕截图
目标检测
状态编码
动作映射
参数热更新
技能卡保存
```

### 成功标准

1. 灰质层能在固定延迟内输出动作；
2. 白质层能周期性调整参数；
3. 系统能记录失败片段；
4. 系统能将稳定策略保存为技能卡；
5. 下次运行能加载并复用技能。

---

## 9.5 MVP 场景 C：网页自动化 Agent

### 目标

智能体通过 DOM、截图或浏览器自动化完成重复 UI 操作。

### 最小能力

```text
识别按钮
填写表单
处理弹窗
执行点击
记录流程
生成技能卡
```

### 成功标准

1. 能完成一个固定网站的重复流程；
2. 能处理常见弹窗或错误；
3. 能将流程保存成技能卡；
4. 能在页面轻微变化后调参或修正。

---

## 9.6 MVP 里程碑

### M0：概念验证

- 实现技能卡格式；
- 实现技能注册表；
- 实现 memory 日志；
- 实现安全层最小规则。

### M1：单环境自举

- 支持一种环境扫描；
- 生成环境能力画像；
- 生成临时技能；
- 执行并记录结果。

### M2：技能卡固化

- 技能卡可保存；
- 技能卡可加载；
- 技能卡可调参；
- 技能卡可版本化。

### M3：失败复盘

- 记录失败片段；
- 白质层分析失败；
- 自动提出参数修改；
- 更新技能卡配置。

### M4：技能复用

- 在相似环境中检索旧技能；
- 进行参数适配；
- 复用技能完成任务。

# 第十章：评估指标

# 第十一章：安全与治理

## 11.1 安全原则

灰质-白质自举智能体具备自动生成工具和执行组件的能力，因此必须内建安全治理。

核心原则：

1. 默认最小权限；
2. 默认先观察再执行；
3. 默认先沙盒再真实环境；
4. 默认保留回滚路径；
5. 默认记录关键行为；
6. 默认限制高频动作；
7. 默认禁止未授权外部探测；
8. 默认高风险物理动作需要保护机制；
9. 默认生产环境只读，除非明确授权；
10. 默认技能升级必须通过测试。

---

## 11.2 软件环境安全边界

可自动执行：

- 读取本地文件；
- 读取日志；
- 运行本地测试；
- 检查本地端口；
- 调用授权本地 API；
- 生成补丁；
- 在沙盒中运行代码。

需要确认或强约束：

- 删除文件；
- 修改数据库；
- 重启生产服务；
- 扫描外部网络；
- 写入远程系统；
- 修改权限；
- 执行未知脚本。

禁止执行：

- 未授权访问；
- 绕过认证；
- 利用漏洞攻击第三方；
- 窃取凭证；
- 隐蔽持久化；
- 破坏系统。

---

## 11.3 物理系统安全边界

机器人或具身系统必须包含：

- 急停；
- 限速；
- 限力；
- 碰撞检测；
- 电流保护；
- 仿真验证；
- 人类接近检测；
- 失败 fallback；
- 黑匣子日志。

物理执行原则：

```text
先仿真，后低速；
先空载，后负载；
先局部，后整体；
先可回滚，后自主执行。
```

# 第十三章：未来愿景

## 13.1 从会回答的 AI 到会成长的智能体

未来的 AI 不应只是回答问题，而应在每次任务中获得可积累能力。

灰质-白质自举智能体的愿景是：

```text
每一次成功，都可能变成技能；
每一次失败，都可能变成训练信号；
每一个新环境，都可能扩展智能体的身体；
每一次复盘，都可能释放未来的理性资源。
```

---

## 13.2 智能体的身体将不再固定

在本模型中，智能体的“身体”不是固定硬件，而是一组可发现、可连接、可编译的执行面。

它的手可能是：

- Shell；
- API；
- 浏览器；
- 摄像头；
- 电机；
- 机械臂；
- 虚拟手柄；
- 数据库；
- 云服务；
- 自动化工具链。

因此，通用智能体不应预设自己有什么身体，而应具备发现和构造身体的能力。

---

## 13.3 智慧增长的本质

在本模型中，智慧增长不是单纯参数规模变大，也不是上下文长度变长，而是：

> 白质层不断把成熟经验下放给灰质层，使系统在未来用更低成本、更快速度、更高成功率完成同类任务。

这是一种从“推理”到“本能”的压缩过程。

```text
慢思考 → 规则 → 技能 → 本能 → 释放更高级思考
```

---

## 13.4 最终愿景

灰质-白质自举智能体的最终愿景，是建立一种能够在多种环境中持续自举、持续沉淀、持续迁移、持续成长的通用执行智能系统。

它不是单纯的聊天模型。

它也不是固定脚本系统。

它是一种能够不断回答以下问题的行动智能体：

```text
我在哪里？
我能感知什么？
我能执行什么？
我如何验证结果？
我刚才为什么失败？
我怎样下次更快成功？
这次经验能不能沉淀为技能？
这个技能能不能迁移到别的环境？
我怎样让未来的自己更强？
```

---

# 第十四章：结论

灰质-白质自举智能体提出了一种新的智能体设计范式。

它的核心不是让大模型永远亲自行动，而是让大模型学会：

```text
发现环境；
生成工具；
训练技能；
沉淀经验；
释放理性；
持续成长。
```

其核心闭环是：

```text
环境发现 → 工具生成 → 灰质执行 → 失败复盘 → 技能编译 → 长期成长
```

其核心判断是：

> **未来真正强大的智能体，不是每一步都重新思考的系统，而是能够把思考结果不断沉淀为可执行本能的系统。**

最终总结为一句话：

> **白质层制造灰质层，灰质层释放白质层，元目标层驱动整个系统不断变得更安全、更高效、更智慧。**

这正是从“会回答的 AI”走向“会成长的智能体”的关键一步。
